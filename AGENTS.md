# Repository instructions for all agents

- Commit changes early and often. Make small, coherent commits as work progresses; do not leave a completed task as one large uncommitted change.
- Check `git status` before staging and after each commit. Stage only files related to the current task, and never commit local databases, backups, credentials, or generated environments.
- Keep documentation aligned with the application behavior and preserve existing user data during storage changes.
- For visual checks, run the app with the repository's Docker Compose setup. Use disposable data for test records.
